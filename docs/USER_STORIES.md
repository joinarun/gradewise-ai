# User stories

| As a teacher I want to | Acceptance |
| --- | --- |
| Prepare a rubric once | Paper and key produce an editable pack. Scores add to the exam total. Only an approved version can be used. |
| Grade many answers | The queue binds each entry to an approved question and persists work across interruptions. |
| Protect student content | Local inference can run without sending the answer. Cloud grading requires explicit permission before a request. |
| Resolve ambiguous answers | The review screen shows evidence, warnings, actual source, and both results when a fallback occurred. |
| Finalize grades | I can approve, reject, or change a score. Exports contain finalized scores. |
| Understand the tradeoff | The workspace reports observed request sources, review rates, and what assumptions were used for cost estimates. |
| Demonstrate the product safely | I can load synthetic sample work without sharing private student data. |
